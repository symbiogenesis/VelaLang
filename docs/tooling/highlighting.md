# Vela editor syntax assets

Vela distributes a [Tree-sitter grammar and highlighting query](../../tools/editor/tree-sitter/)
and a [TextMate extension](../../tools/editor/textmate/). These supply local syntax
coloring when a language server is unavailable, including incomplete source.
The pinned independent consumers are Tree-sitter CLI `0.25.10` and the VS Code
tokenization engine `vscode-textmate` `9.2.0` with `vscode-oniguruma` `2.0.1` on
Node.js `22.22.1`. The executable consumer qualification currently targets Linux
ARM64; these text assets carry no claim of qualification in every editor or host.

The [Menhir grammar and lexer](parser.md) own syntax. The
[generator](../../tools/toolchain/highlight.py) translates Menhir productions,
expands parameterized list rules and removes semantic actions. It emits explicit
GLR conflicts for lexical contexts that Menhir's lexer classifies with lookahead.
The TextMate keyword inventory and Tree-sitter query use the same compiler lexer.
The original [external scanner](../../tools/editor/tree-sitter/src/scanner.c)
handles nested block comments, arbitrary raw-string quote delimiters and bounded
interpolation nesting. Generated upstream C parser/runtime files and consumer
packages stay outside the tracked source tree.

## Use and regeneration

The TextMate directory contains a VS Code language-extension manifest and
`source.vela` grammar for `.vela` files. It can be loaded as a local extension;
it supplies no semantic-token provider or language server. The Tree-sitter
directory supplies ABI-15 grammar metadata and `queries/highlights.scm` for
Tree-sitter consumers. Build it with the pinned generator in a copied working
directory; the generated parser can then be loaded by a compatible syntax-aware
consumer. Highlighting queries classify lexical names, literals, keywords,
comments and punctuation; they assert no resolved symbol identity.

Run `python tools/run.py vela-highlight check` to verify generated bytes, or
`python tools/run.py vela-highlight generate` to explicitly refresh them after
changing canonical syntax. The repository `check` gate also rejects asset drift.
Check and qualification preserve authored source bytes.

## Executable qualification

Provision the exact consumers recorded in
[THIRD-PARTY.md](../../THIRD-PARTY.md#independent-syntax-consumers), retaining their
licenses and notices beside the external packages. Qualification performs no
downloads or installation. On Windows, the following command dispatches to WSL;
use guest paths for consumer arguments:

```powershell
python tools/run.py vela-highlight qualify `
  --tree-sitter /path/to/tree-sitter `
  --textmate-package /path/to/vscode-textmate `
  --oniguruma-package /path/to/vscode-oniguruma `
  --node /usr/bin/node `
  --output out/highlight-qualification.json
```

On Linux use `python3 tools/run.py` with the same arguments on one shell command
line. Reports must be regular `.json` files beneath repository `out/` and cannot
alias selected consumer inputs. Exact executable/package bytes are checked before
use and again with canonical source/asset bindings immediately before atomic
report publication. Reports bind grammar/query bytes, both generator modules, the
shared corpus and recovery inventory, compiler lexer/grammar and the canonical
parser's own build receipt.

The [qualifier](../../tools/toolchain/highlight_qualification.py) exercises all six
authored examples and the complete versioned
[surface corpus](../../tools/toolchain/surface.py): 76 positives and 319 negatives.
It independently rechecks the canonical parser's expected results, then checks
each projected Tree-sitter result against the frozen
[recovery dispositions](../../tools/editor/recovery.json). The stock query engine
renders Unicode HTML whose decoded text must equal the exact source, and the
stock TextMate engine tokenizes every projected shared-corpus source. Independent
[fixtures](../../tools/editor/fixtures.json) additionally assert token scopes for
nested comments, raw delimiters, escaped characters, dependent generic syntax,
Unicode, nested interpolation braces and lifetime apostrophes. Eight edits compare
complete incremental and fresh Tree-sitter trees, including byte ranges, for
valid changes, incomplete comments/generics/raw strings and repairs.

Resource bounds are 65,536 UTF-8 source bytes, two seconds per Tree-sitter parse,
60 seconds per consumer process and 100 milliseconds per TextMate line. Scanner
comment/interpolation nesting is limited to 256. Timeouts, changed consumers,
unexpected recovery, stale generated assets and malformed fixture outcomes fail
qualification; they cannot yield a successful syntax-assets report.

## Recovery and acceptance boundaries

The editor parser approximates lexical lookahead and omits compiler semantic
actions. One canonical positive, structural local/lambda annotations, currently
uses recovery. Thirty-five canonical syntax negatives retain an editor tree:
reserved words in contextual identifier positions; declaration modifiers and
constant/proof-signature restrictions; constructor-pattern spellings and complete
binding shape; retired null spellings; bare type-shaped locals; raw-string layout;
and empty interpolation expressions/specifiers. Their exact names and current
dispositions are executable expectations, not compiler acceptances. Invalid
UTF-8 and compiler resource-limit cases retain their canonical refusals and are
outside the projected editor envelope.

Lexical highlighting deliberately tolerates malformed numeric separators and
escapes, and interpolation scanning does not validate expression punctuation,
nonempty format specifiers or line-break legality. Explicit negative neighbors
show these recovering as syntax coloring while the canonical lexer refuses them.
TextMate keeps an unfinished string/comment scope through the available text;
Tree-sitter instead exposes `ERROR` or missing nodes. Nested interpolation braces
and lifetime apostrophes are supported and independently checked. There are no
embedded foreign-language injections.

Every report states `semantic_acceptance: false`. Neither successful parsing,
recovered highlighting nor matching incremental trees authorizes Vela checking,
proof acceptance, source correspondence or artifact admission. Those judgments
remain with the [compiler/tooling contract](tooling-protocols.md#syntax-grammars-and-highlighting).
